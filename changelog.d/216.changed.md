- **`(pxf.required)` with `(pxf.default)` on one field is now refused when the schema binds** ([#216](https://github.com/trendvidia/chameleon/issues/216)). Read this if a schema of yours has both, in either spelling (`[(pxf.required) = true, (pxf.default) = "x"]`, `@required @default("x")`, or a mix). `resolver.New`, `chameleon check-schema` and `chameleon bundle` now fail on it with `(pxf.required) and (pxf.default) are exclusive on one field`, whichever spelling the schema used. Draft -01 of the PXF spec forbids the pair ("Required and Default", [protowire#453](https://github.com/trendvidia/protowire/issues/453)).

  **This changes what chameleon did.** chameleon ran its defaults pass first, so a default answered for the requirement and the field could never be missing. protowire-go checks required first, so the same schema failed there. One schema meant two things, and the requirement on it never fired here.

  **What to do.** Decide which one you meant. If the field should fall back to a value, drop `(pxf.required)`: that keeps exactly what chameleon did. If an operator must set it, drop `(pxf.default)`. `(pxf.required) = false` beside a default demands nothing and stays accepted.

  chameleon does this check itself because the protowire-go release it pins does not carry it yet ([protowire-go#204](https://github.com/trendvidia/protowire-go/pull/204)). Its local check goes away once a release does.
